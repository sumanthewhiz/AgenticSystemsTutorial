Appendix AGlossary

Plain-language definitions of every term used in the tutorial, each linked to the chapter that teaches it.

A

A2A (Agent2Agent) - An open protocol for agent-to-agent discovery and task exchange. See Chapter 10.

Abstention - A model or agent choosing not to decide when evidence is weak or contradictory. See Chapter 9.

Action catalog - The allowlist of state-changing operations an agent may propose, each with typed parameters and verification. See Chapter 21.

Agent - A component that uses a model, tools and state to decide part of a task. See Chapter 1.

Agent card - A machine-readable description of an agent's identity, skills and endpoints. See Chapter 10.

Agent loop - The repeated observe, think, act and observe cycle often called ReAct. See Chapter 1.

Analyst agent - SwarmPipe's governed natural-language-to-SQL agent for published data. See Chapter 20.

Approval - A durable human decision that lets a prepared action continue, often with typed confirmation. See Chapter 21.

Audit log - A durable, tamper-evident record of decisions and side effects. See Chapter 22.

Autonomy ladder - SwarmPipe's L0-L4 scale from inform-only to autonomous execution, earned with evidence and withdrawn after failures. See Chapter 21.

B

Backpressure - Admission control that slows or stops new work when queues are too deep. See Chapter 5.

Blackboard - Shared case state where agents append findings, evidence and decisions. See Chapter 8.

Blast radius - The downstream consumers, datasets or reports affected by an action or bad batch. See Chapter 7.

Blue/green publish - Publishing by staging a new immutable version and then repointing a stable view. See Chapter 7.

Bulkhead - A concurrency boundary that keeps a slow dependency from starving unrelated work. See Chapter 13.

C

Canary - A limited rollout to a small cohort before general availability. See Chapter 18.

Checkpoint - A persisted step result that lets a workflow resume without replaying earlier work. See Chapter 12.

Circuit breaker - A control that stops publishing or dependency calls when failures cross a threshold. See Chapter 6.

Compensation - A saga rollback action that semantically undoes a side effect. See Chapter 12.

Context engineering - Selecting, labeling and compressing the right information for a model call. See Chapter 11.

Control plane - The governance, identity, policy, model, tool and eval machinery that controls agents. See Chapter 2.

Critic - An evaluator agent that reviews another agent's proposal using independent evidence. See Chapter 8.

D

Data contract - A versioned agreement for schema, semantics, freshness and quality. See Chapter 6.

Data plane - The workflows, watcher, event bus, warehouse and files that move and transform data. See Chapter 2.

Dead-letter queue (DLQ) - Storage for work that failed permanently and needs operator attention. See Chapter 5.

Delegation - Acting on behalf of a user while intersecting user and agent permissions. See Chapter 20.

Deterministic fallback - Non-model logic used when the model is unavailable or untrusted. See Chapter 1.

Durable execution - Running workflows so crashes, retries and waits do not lose progress. See Chapter 12.

E

Egress allowlist - A control that permits outbound communication only to approved destinations. See Chapter 19.

Embedding - A vector representation used for semantic retrieval; SwarmPipe uses BM25 locally instead. See Chapter 11.

Error budget - The allowed amount of unreliability before a team slows feature changes. See Chapter 23.

Eval case - A versioned input, expectation and scoring rule for measuring behavior. See Chapter 15.

Eval flywheel - The loop of production feedback becoming new regression cases. See Chapter 18.

Evidence id - A stable citation id attached to a tool result or observation. See Chapter 11.

Evidence pack - An export containing signals, data snapshots, evidence, policy, approvals, actions, verification and audit anchors. See Chapter 22.

F

Fan-in - Merging parallel work back into one decision or output. See Chapter 8.

Fan-out - Splitting work into parallel child tasks or specialist investigations. See Chapter 8.

Feature flag - A runtime switch that changes behavior without editing code. See Chapter 26.

Fencing - Preventing a worker with a lost lease from continuing side effects. See Chapter 12.

Freeze window - A policy period where risky actions are escalated to approval. See Chapter 26.

G

GA (General availability) - The broad rollout stage after evals, shadow and canary evidence. See Chapter 18.

GenAI semantic conventions - OpenTelemetry attribute names for model, agent and tool spans. See Chapter 23.

Groundedness - The degree to which a claim is supported by cited evidence. See Chapter 11.

Guardrail - A deterministic or model-assisted control that reduces unsafe behavior. See Chapter 19.

H

Hallucinated citation - A citation id or source reference that does not exist in the provided evidence. See Chapter 11.

Hash chain - A sequence where each audit row includes the previous hash, making tampering evident. See Chapter 22.

Health check - A liveness probe that tells whether the service can answer. See Chapter 26.

Human-in-the-loop - A design where a human approves, rejects or supplies judgment for risky steps. See Chapter 21.

I

Idempotency key - A key that makes repeated side-effect attempts execute at most once. See Chapter 12.

Immutable version - A dataset version that is never edited after creation. See Chapter 7.

Incident - A correlated set of signals that needs diagnosis and possibly remediation. See Chapter 9.

Indirect prompt injection - Malicious instructions hidden in data, documents or tool results. See Chapter 19.

Ingestion - Turning files in the watched folder into durable workflow runs. See Chapter 5.

Investigator - A read-only specialist agent that gathers cited evidence for one failure family. See Chapter 9.

J

Judge - A model used to score open-ended output against a rubric. See Chapter 16.

Judge calibration - Measuring judge agreement with human labels and bias before trusting scores. See Chapter 16.

K

Kill switch - A scoped control that stops model calls or actions immediately. See Chapter 22.

Knowledge poisoning - Corrupting retrieved documents or memory so future agents receive bad guidance. See Chapter 11.

L

Lease - A time-limited claim on a run that expires if a worker dies. See Chapter 12.

Lethal trifecta - The risky combination of private data access, untrusted content and external communication. See Chapter 19.

Lineage - Metadata describing datasets, jobs, versions and dependencies. See Chapter 7.

LLM gateway - The shared path for model routing, budgets, cache, breakers, validation and fallback. See Chapter 3.

M

MCP (Model Context Protocol) - A protocol for exposing tools and data sources to model clients. See Chapter 10.

Memory - Stored knowledge from runs, lessons or curated documents. See Chapter 11.

Model certification - Running role-specific evals before trusting a model in that role. See Chapter 25.

Model profile - A configured model routing chain such as offline, Ollama, Azure or OpenAI. See Chapter 25.

Multi-agent system - A system where multiple agents cooperate through routing, handoff, fan-out or shared state. See Chapter 8.

N

Natural-language-to-SQL - Translating a user question into read-only governed SQL. See Chapter 20.

Non-determinism - Variation in model output across attempts, measured rather than ignored. See Chapter 15.

O

OIDC - OpenID Connect, the production identity mechanism that replaces demo headers. See Chapter 20.

On-call ergonomics - Designing alerts, approvals and runbooks so tired humans can act safely. See Chapter 26.

OpenLineage - An open specification for job and dataset lineage events. See Chapter 7.

OpenTelemetry - A standard for traces, metrics and logs across services. See Chapter 23.

Out-of-band change - A direct data edit that bypasses the pipeline. See Chapter 7.

P

pass@k - The probability that at least one of k attempts succeeds. See Chapter 15.

pass^k - The probability that all k attempts succeed, a stricter reliability view. See Chapter 15.

PII tokenization - Replacing personal data with stable tokens unless an authorized identity detokenizes it. See Chapter 20.

Policy-as-code - Deterministic authorization rules stored and reviewed as code. See Chapter 21.

Poison file - An input crafted to crash parsing, mislead a model or carry malicious instructions. See Chapter 14.

Postmortem - A blameless explanation of what happened and how to prevent recurrence. See Chapter 9.

PRD - Product requirements document; for AI features it must include eval and safety requirements. See Chapter 27.

Prompt lock - A lockfile of approved prompt hashes enforced at runtime. See Chapter 18.

PSI (Population Stability Index) - A drift metric comparing current and baseline distributions. See Chapter 6.

Q

Quality check - A data-health assertion such as row count, schema, accepted values, freshness or drift. See Chapter 6.

Quarantine - Storing bad or suspicious data without publishing it to consumers. See Chapter 6.

R

Readiness check - A probe that tells whether the platform is ready to process work. See Chapter 26.

ReAct - An agent pattern that interleaves reasoning and tool actions. See Chapter 1.

Red team - Purposefully attacking the system to measure containment. See Chapter 17.

Redrive - Requeueing dead-lettered work after the cause is understood. See Chapter 26.

Rollback - Reverting a state change by repointing versions, restoring snapshots or running compensation. See Chapter 12.

Router agent - The agent that classifies arriving files as tabular, document or unsupported. See Chapter 2.

Run - A durable workflow execution with steps, state, attempts and trace id. See Chapter 12.

Runbook - A documented procedure for diagnosing and responding to an operational condition. See Chapter 26.

S

Saga - A sequence of side effects paired with compensations. See Chapter 12.

Scenario - A SwarmPipe synthetic input or fault you can drop into the inbox. See Chapter 0.

Shadow mode - Running a candidate prompt or model beside production without acting on it. See Chapter 18.

Signal - A deterministic observation such as schema drift, freshness overdue or SLO breach. See Chapter 9.

SLO - Service level objective, a target for reliability measured by an SLI. See Chapter 23.

Spotlighting - Marking untrusted data boundaries in prompts so the model treats content as data, not instructions. See Chapter 19.

Structured output - Model output validated against a schema. See Chapter 3.

Supervisor - The triage agent that plans investigations and owns the final diagnosis. See Chapter 9.

SwarmPipe - The local, offline-by-default multi-agent data pipeline used throughout the tutorial. See Chapter 0.

T

Tenant isolation - Keeping data, quotas, autonomy and permissions separated by tenant. See Chapter 20.

Telemetry - Operational traces, metrics and logs used for debugging and SLOs. See Chapter 23.

Tool gateway - The shared path that validates tool calls, scopes, evidence ids and fingerprints. See Chapter 4.

Trace - A tree of spans showing one request, run or incident across agents and tools. See Chapter 23.

Trust label - A marker such as trusted, unverified or untrusted attached to retrieved context. See Chapter 11.

V

Verifier - The deterministic agent that checks ground truth after an action. See Chapter 9.

Version pinning - Recording the prompt, model, tool and agent versions used for a decision. See Chapter 22.

W

Watched folder - The local inbox where files arrive for ingestion. See Chapter 5.

Workflow - A deterministic sequence of durable steps. See Chapter 12.

Workload identity - A service identity used by software rather than a human. See Chapter 20.
